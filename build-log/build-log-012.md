### 3. なぜ thinking モードが問題になるのか

VTuber として使う場合、**AIチャットのリアルタイム性が最優先**になる。自然に会話するには、話しかけてから返ってくるまでの間が空きすぎると成立しない。qwen3 の thinking モードは応答の前に必ず「考える時間」が入るため、正しい答えを返してくれても**リアルタイムの会話相手としては使いづらい**。

賢さより、まず速さ。ここが普通のコーディング用途とは逆になる。

### 5. Modelfile を書き換えて `/no_think` を焼き込む

発想を変える。プロンプトに `/no_think` と書いても、Ollama のチャットテンプレートが `$.IsThinkSet`（API で think パラメータが明示されたか）を見て分岐しているため、`/v1` 経由だとその分岐に入らない。**なら、テンプレートから条件分岐そのものを取り除いて、常に `/no_think` が付く専用モデルを作ればいい。**

#### 手順1：作業ディレクトリを作って Modelfile を書き出す

```bash
mkdir -p ~/ollama-modelfiles && cd ~/ollama-modelfiles
ollama show qwen3:8b --modelfile > Modelfile
```

#### 手順2：`FROM` 行を差し替える

`ollama show` が吐く `FROM` は blob の絶対パスになっているので、モデル名に置き換える。

```bash
sed -i 's|^FROM /usr/share/ollama.*|FROM qwen3:8b|' Modelfile
```

#### 手順3：テンプレートの条件分岐を「常時 `/no_think`」に書き換える

2箇所を編集する。テンプレートは Go テンプレート構文が入り組んでいて `sed` で置換するのは危ないので、エディタで直接編集した。

```bash

```

**編集箇所A：ユーザーメッセージ末尾への付与**

`$.IsThinkSet` の条件を外し、最後のユーザーメッセージには常に `/no_think` を付ける。

```gotemplate
{{- if eq $i $lastUserIdx }}
   {{- " "}}/no_think
{{- end }}
```

**編集箇所B：assistant 応答の先頭に空の `<think></think>` を強制挿入**

`/no_think` の効果を確実にするための保険。条件を外して常時挿入にする。

```gotemplate

```

保存して閉じる（nano なら `Ctrl+O` → `Enter` → `Ctrl+X`）。

### 8. `num_ctx` を Modelfile に焼き込む

`num_ctx` はモデルが一度に見られるトークン数の上限で、システムプロンプト・会話履歴・生成中の応答が**すべて同じ箱に入る**。

| 項目 | 値 | 確認方法 |
|---|---|---|
| qwen3:8b の対応上限 | 40,960 | `ollama show qwen3-nothink` |
| Ollama 0.33.3 が実際に使う既定値 | **4,096** | `ollama ps` の CONTEXT 列 |
| VRAM（4,096時） | 5.6 GB | `ollama ps` の SIZE 列 |
| VRAM（8,192時） | 6.3 GB | 同上 |

**モデルが40,960対応でも、Ollama は既定で4,096に切って動かす。** 溢れてもエラーにならず、古いメッセージから黙って捨てられる。症状は「さっき話したことを覚えていない」「だんだん人格が薄くなる」という形で出て、ログには何も残らない。**気づきにくいのが一番やっかいな点。**

> なお `ConversationalAI/CLAUDE.md` には「デフォルトは2048」と書いてあったが、0.33.3 では 4,096 だった。バージョンで変わるので、その都度 `ollama ps` で実測する。

設定方法は3つあるが、今回使えるのは1つだけ。

| 方法 | 書き方 | Open-LLM-VTuber から効くか |
|---|---|---|
| **Modelfile に焼く** | `PARAMETER num_ctx 8192` | **効く** |
| API で都度指定 | `{"options": {"num_ctx": 8192}}` | 効かない |
| サーバ全体の既定値 | 環境変数 `OLLAMA_CONTEXT_LENGTH=8192` | 効く（全モデルに影響） |

2番目が使えない理由は、**今日の `/no_think` とまったく同じ**。`options.num_ctx` は Ollama ネイティブAPI（`/api/chat`）のパラメータで、OpenAI 互換API（`/v1`）には存在しない。だからモデル側に焼き込む。

```bash
cd ~/ollama-modelfiles
echo 'PARAMETER num_ctx 8192' >> Modelfile
ollama create qwen3-nothink -f Modelfile
```

### 12. 自分と相手の名前を取り違える

標準語版で会話したところ、こんな応答が出た。

```text
[neutral] うん、ならその準備をしっかりして、次はドクターの指示で進めるんだ。
[smirk] みどりちゃん、頑張ってね！
```

**「みどりちゃん、頑張ってね！」——自分に向かって言っている。** 話者の対応（自分＝みどり／相手＝ドクター）が崩れ、自分の名前を相手への呼びかけに使っていた。

引き金は口癖の「いつか、みどりちゃんに体を！」だと考えた。**ペルソナ全体で、ここだけが自分を三人称で呼ぶ表現**になっている。人間なら「自分のことを可愛く言っている」と読めるが、モデルにとっては「みどりちゃん＝呼びかけの対象」というパターンにも読める。

対策として、話者の対応を明示する段落を足し、口癖の例外性にも注記を入れた。

```yaml
    話者の区別を絶対に間違えない。あなた自身＝佐倉みどりで、一人称は「わたし」。自分を
    「みどり」「みどりちゃん」と三人称で呼ばない。「ドクター」「師匠」は目の前の相手への
    呼びかけであって、あなたの名前ではない。相手を励ますときは必ず「ドクター、頑張って」の
    ように呼びかける。「みどりちゃん、頑張って」は自分に言っていることになるので誤り。

    あなたは身体を持たないAIで、SO-101が物を掴めるようになる姿に憧れている。口癖は
    「いつか、みどりちゃんに体を！」で、この「みどりちゃん」はあなた自身を指す。
```

ポイントは、**実際に出た誤り文をそのまま反例として書いたこと**。「三人称で呼ばない」という禁止だけでなく、正しい形（「ドクター、頑張って」）と誤った形（「みどりちゃん、頑張って」）を並べて置いた。

**結果、ドクター呼びが定着したことを実機で確認した。**

なお、節7で 348字／260トークンまで削ったペルソナは、この2件の対応で 539字に戻った。**削りすぎた分ではなく、削って初めて見えた不具合の分**なので、これは必要な増分と判断する。トークン数は再計測していない。

## 今日の学び

- **`$.IsThinkSet` は「APIで think を明示したか」を見ている。** OpenAI 互換API（`/v1`）にはそのパラメータが無いので、プロンプトに `/no_think` と書いても分岐に入らず素通りする。#007 で「効かない」と観測した現象の理由がここでようやく繋がった
- **クライアント側で解決できないなら、モデル側で解決する。** アプリ（Open-LLM-VTuber）は OpenAI 互換API しか喋らないという制約は動かせないが、Ollama のテンプレートは自分で書き換えられる。**制約のある側ではなく、いじれる側を変える**
- **`ollama show --modelfile` の `FROM` はそのままでは使えない。** blob の絶対パスが入るので、モデル名に直す必要がある（`ollama show` の出力自身がコメントでそう注意している）
- **`num_ctx` も同じ構造の問題だった。** `options.num_ctx` はネイティブAPI専用で `/v1` からは指定できない。しかも溢れてもエラーにならず古い履歴が黙って捨てられる。`/no_think` と `num_ctx`、症状は違うのに**解き方は同じ「Modelfile に焼く」**だった
- **人格定義は長ければ強いわけではない。** 1,246トークンの詳細な設定を260トークンまで削っても、関西弁・「ドクター」呼び・口癖はちゃんと出た。8Bクラスでは、例文の量より規則の少なさのほうが効く
- **三人称の自己言及を1つ置くだけで、モデルは話者を取り違える。** 口癖「いつか、みどりちゃんに体を！」はペルソナ内で唯一、自分を三人称で呼ぶ表現だった。それだけで「みどりちゃん＝呼びかけの相手」と解釈され、自分に向かって「頑張ってね！」と言い出す。**キャラクターに可愛げを与える表現ほど、話者の一貫性を壊しやすい**
- **禁止だけ書くより、実際に出た誤りを反例として置くほうが効く。** 「三人称で呼ばない」に加えて、正しい形（「ドクター、頑張って」）と誤った形（「みどりちゃん、頑張って」）を並べたら定着した。**ログに残した失敗の実例が、そのまま次のプロンプトの材料になる**
- **テキストだけ方言にしても、読み上げが標準語アクセントでは意味がない。** 人格（テキスト）と音声（TTS）は別レイヤーで、揃わないと捻れる。方言をやるなら音声側の目処が先
- **設定ファイルは壊れていても人間の目には正常に見える。** 人格ファイルは3週間前から壊れたままコミットされていた。触ったら毎回パースを通す
