# Build Log #006 — 2026-07-28

## 今日やったこと

### 1. 学習済みポリシーの実機推論（`lerobot-rollout`）

Build Log #005で学習した`emboss369/act-yellow-lego-to-white-case`（ACTポリシー、Day1・50エピソード・20,000ステップ）を実際にフォロワーアームへ推論させ、「黄色いレゴブロックを白いケースに入れる」タスクを評価した。

実行コマンド：

```bash
lerobot-rollout \
    --robot.type=so101_follower \
    --robot.port=$FOLLOWER_ARM \
    --robot.id=right_follower_arm \
    --robot.cameras='{
        wrist: {type: opencv, index_or_path: 0, width: 640, height: 480, fps: 30},
        front: {type: opencv, index_or_path: 2, width: 640, height: 480, fps: 30}
    }' \
    --policy.path=emboss369/act-yellow-lego-to-white-case \
    --fps=30 \
    --task="Put the yellow lego block into the white case" \
    --display_data=true \
    --duration=0
```

**結果：完全成功。** 掴む→運ぶ→白いケースに入れる、までタスクを完遂した。M1 Mac環境での先行事例（200エピソード学習でも実用的に掴めなかった、という記事）と比べ、今回は50エピソードのみでの成功。あわせて、動きにカクつきがなく滑らかだった点も確認できた。

### 2. 掴める位置とそうでない位置の切り分け（条件付き成功であることの確認）

実行中、ブロックの置き場所を変えて試したところ、成否がはっきり分かれた：

- **データ収集時（Day1、50エピソード）にブロックを置いていた場所付近**：安定して掴めた
- **それ以外の、これまで置いたことのない離れた場所**：掴めなかった

つまり今回の「成功」は、タスク全般を汎化して解けているのではなく、**学習データに含まれる位置周辺でのみ**再現できている状態だと分かった。

## 結果（成功／失敗／保留）

- 成功（ただし条件付き：学習データの範囲内の配置位置に限る）

## 失敗の原因・学んだこと

- **位置汎化の欠如**：50エピソードの記録時、ブロックの配置位置にバリエーションを持たせていなかったため、ポリシーが「どの位置にあっても黄色いブロックを認識して掴む」という一般的な視覚運動マッピングではなく、位置に強く依存した振る舞いを学習した可能性が高い。次回以降のデータ収集ではブロックの置き場所を意図的にばらつかせる必要がある
- **動きが滑らかになった原因は未確定**：「RTX 5060 Tiで推論が追いつくようになったから」という仮説を立てたが、ログには`Record loop is running slower (5.0 Hz) than the target FPS (30.0 Hz)`という警告が起動直後に1回だけ出ている。以後83秒間再出力がなかったため、①起動直後のCUDAウォームアップで一瞬落ちただけで以後は追いついた、②実は最後まで遅かったがログ上は判別できない、のどちらかは今回のログだけでは確定できない。加えて、ACTポリシー自体が行動チャンキング（action chunking）＋temporal ensembleにより単発の反応ではなく先読みした一連の動作を出力する設計のため、推論速度と無関係にそもそも滑らかになりやすい可能性もある。**「GPU推論速度」と「ACTのアーキテクチャ」のどちらが滑らかさの主因かは仮説段階**であり、事実として確定しているのは「M1 Mac比で体感上滑らかだった」ことのみ
- **ログ表示の小さな食い違い**：`--robot.type=so101_follower`を指定したにもかかわらず、ログには`Connecting robot (so100_follower)...`と表示された。接続・動作自体は正常だったため実害は確認されていないが、内部で共通クラスを使っている場合の表示ゆれの可能性があり、次回以降も注意して見ておく
